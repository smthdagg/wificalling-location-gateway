# v1.3.0-r9 WLOC reliability verification

## Scope

This release keeps the integrated `1.3.0-r1` Gateway baseline and changes
only the maintained WLOC path: exact host coverage, minimum response rewrite,
independent HTTP/2 stream handling, and proxy-health classification.

## Tests written before the final health fixes

1. `rejected_client_tls_does_not_degrade_proxy_health` was added before the
   classifier. It initially failed because `proxy_error_degrades_health` did
   not exist; it now proves that `ClientTls` is not a service failure while an
   upstream failure is.
2. `startup_health_snapshot_drops_prior_process_failures` was added before the
   startup reset. It initially failed because `reset_proxy_health` did not
   exist; it now proves an old `failures: 43` snapshot becomes a fresh
   `{ failures: 0 }` snapshot at daemon start.
3. Existing integration coverage verifies that only existing latitude,
   longitude, and horizontal-accuracy fields change, all other response/root
   fields pass through, and a failed upstream HTTP/2 stream resets only that
   stream.

80.90%, Cargo advisory/license checks passing, and repository gates passing.

## AX6S evidence

The final service binary was installed on the authorized AX6S and restarted.
`wloc-ctl status` reported `service_phase: intercepting`, manual geo source,
healthy shared engine, IPv4 redirect present, and `forward_original` response
mode. The fresh `proxy-health.json` read `failures: 0`; only one WLOC daemon
and one Gateway-owned sing-box remained. Post-test available memory was about
48 MiB and `/tmp` had about 80 MiB free, both above the project gate.

The user then observed the manual target after only a brief transient error.
No raw device traffic, credentials, location coordinates, or node details are
recorded here.
