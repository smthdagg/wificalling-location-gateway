# v1.2.2 AX6S runtime hotfix verification

Date: 2026-08-23

## Scope

This hotfix is based on the final integrated WiFi Calling + WLOC `v1.2.2`
release. It does not import the retired standalone WiFi Calling 1.7 code and
does not change the paused 2.x redesign.

## Reproduced failures (RED)

- `tests/scripts/test-monitor-temp-cleanup.sh` reproduced one leaked
  `events.log.tmp.*` file per monitor pass.
- `tests/scripts/test-wloc-synthesis-default.sh` showed that the existing
  local WLOC synthesis path was not enabled by the OpenWrt service.
- `upstream_connect_failure_is_reported_to_proxy_health` showed that an Apple
  upstream connection failure was incorrectly returned as a successful proxy
  connection.
- `tests/scripts/test-wloc-listener-nonblocking.sh` reproduced the missing
  nonblocking transition before the TPROXY listener was handed to Tokio. On
  AX6S this left ClientHello bytes unread and made WLOC TLS connections time
  out intermittently.

## Implemented fixes (GREEN)

- Remove the monitor temporary event file after it has been appended.
- Enable the already implemented local WLOC response synthesis path in procd.
- Return upstream errors to the proxy-health recorder.
- Set the transparent TCP listener nonblocking before
  `tokio::net::TcpListener::from_std`.

All targeted regression tests passed after the corresponding implementation.

## Repository verification

`./scripts/ci/verify.sh` passed after the final listener fix. This includes the
shell regressions, Python tests, JavaScript tests, Rust unit/integration tests,
formatting, linting, release build, secret scan, dependency policy, and
packaging gates. Final Rust line coverage was 81.06%.

The AX6S service binary was cross-compiled with the pinned OpenWrt 24.10.8
mediatek/mt7622 toolchain. The resulting executable is an AArch64 ELF64 static
binary with no dynamic `NEEDED` entries.

Package SHA-256:
`b41641f86ba4ced4f0278167d5627b17da5c1c9fdcb7bdf67f679cf80d75c8d8`

- Existing WCG and WLOC UCI configurations were preserved byte-for-byte.
- WCG, its monitor loop, and WLOC remained running with stable PIDs during a
  30-second observation window.
- The 439 historical zero-byte monitor temporary files were validated before
  removal. The count stayed at zero after the fix.
- Five independent TLS/HTTP2 synthetic WLOC requests returned HTTP 200 in
  20-65 ms. Five rewrite events were recorded and no request used the Apple

- Eight WCG node profiles and one device profile were present; the generated
  WCG monitor contained that device.
- The LuCI `luci.wloc health` RPC reported WLOC running with its control socket
  present and phase `intercepting`. It also reported WCG running, sing-box
  running, a valid generated configuration, one device, and all eight nodes
  reachable.
- At the end of testing the router reported about 26 MiB available memory and
  15 MiB available overlay storage.

## Remaining live-device gate

The iPhone was idle/offline in the neighbor cache after deployment and emitted
no new WLOC request during the final observation window. Its last observed
WLOC request was before the hotfix installation. The router-side WLOC path is
verified, but a fresh Maps/location action on the iPhone is still required to
record post-install device evidence.

The WCG monitor also remained `no_session`: no IKE/UDP 500 or NAT-T/UDP 4500
traffic was initiated by the iPhone during the final window. The gateway node
configuration and processes are present, but Wi-Fi Calling registration must
be triggered on the phone before that client-side gate can be accepted.

## Rollback

A pre-install configuration, certificate, package-status, and runtime-file
backup is stored on the router under
`/tmp/wlg-v122-hotfix-backup-20260823`. This path is volatile and disappears
after a router reboot.
