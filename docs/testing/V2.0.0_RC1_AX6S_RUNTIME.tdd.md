# v2.0.0-rc1 AX6S runtime evidence

This evidence records the AX6S test of the unified Wi-Fi Calling Gateway and
WLOC candidate package. No device credentials, private keys, raw traffic, or
precise user location are recorded here.

## Package

- Version: `2.0.0-rc1-1`
- Target: `aarch64_cortex-a53`
- SHA-256: `ac03f68548d1a1be506217dff82e6caaeffba027ba8d00bb398ddf399bf54858`
- Package size: approximately 1.4 MiB

## Installation and runtime checks

- Existing `1.2.2-r3` package was removed before installation because the
  AX6S overlay had limited free space.
- The candidate installed successfully and retained the existing modified UCI
  configuration as package-managed `.opkg` copies.
- `wificalling-location-gateway` reported `2.0.0-rc1-1` after installation.
- WCG monitor and sing-box were running; all 8 configured nodes reported OK.
- WLOC control socket was present and the health projection reported a fresh
  exit result, fresh Geo evidence, and `intercepting`.
- The default device profile was bound to one configured LAN device and its
  WLOC table contained only the approved WLOC destination set.
- `wloc-ctl refresh --profile default` returned a successful v1 control
  response.
- Re-running the redirect synchronizer twice returned success both times,
  left exactly one WLOC policy rule, and kept the WLOC table present.
- Three process snapshots over approximately 20 seconds showed stable WLOC
  and Gateway sing-box PIDs.

## Resource observation

At the post-install check, the AX6S reported approximately 37 MiB free memory
and 30 MiB available memory with no swap. The overlay reported approximately
13 MiB free space. This is a candidate measurement only; the v2 release ADR
still requires a longer resource budget run before a final `v2.0.0` release.

## Automated gates

`./scripts/ci/verify.sh` passed after the release-candidate changes:

- 80 Python tests
- Rust unit and integration tests
- LuCI, shell, package, and secret-scan checks
- OpenWrt cross-build checks
- Cargo audit, deny, and license checks
- Line coverage: 80.44%

The x86_64 package build was not included in this candidate evidence because
the fixed Rust standard-library download endpoint was throttled during the
release run. No stale x86_64 binary was substituted.
