# v2.0 task breakdown and ownership

Status: implementation complete; PR #60 is green and the project lead owns
integration and acceptance. This document is the implementation checklist, not
itself a release approval. The product boundary is the integrated WiFi Calling
Gateway + WLOC project; ADR 0004 supersedes the earlier standalone-WLOC
wording. The signed V2 feed is prepared locally; gh-pages/tag/release
publication remains after PR merge and the explicitly open client/physical
fault gates.

## Current implementation checkpoint

Completed and re-verified on the V2-09 branch:

- bounded `ProfileRuntimeManager` with independent enable/disable/degraded
  state and shared-engine health gating;
- profile-scoped OpenWrt nftables tables, exact TCP/443 rule shape, approved
  Apple set refresh, independent cleanup, and package inclusion;
- redacted per-profile health projection and a unified LuCI device-profile
  page/status table;
- bounded WLOC event log (64 KiB), provider/device activity log (configurable
  default 64 KiB), synthesized-client cache, and debug sample files.
- V2-04 source-device profile patch routing, independent per-profile probe/Geo
  handlers, auto/manual target isolation, and redirect-gated route activation.
- unified supervisor health checks bound to the real WLOC socket, proxy listener,
  exact service PID and WLOC-owned state;
- UCI-backed v2 profile CRUD with commit/revert behavior, plus LuCI per-device
  settings and independent monitor/log selection;
- redacted profile-aware support bundles, opt-in bounded debug capture, and
  short nft destination leases that expire after a hard kill.
- shared sing-box provider resolution that prefers AX6S-tested tiny/lite or
  PassWall binaries without adding a duplicate package payload. When both
  modules are enabled, WLOC reuses the Gateway-generated sing-box config.

Release acceptance status:

- package, UCI, init, RPC, LuCI, and build paths contain both Gateway and WLOC;
  the package is independent from the separate external Gateway 1.7 project;
- the integrated supervisor owns both child lifecycles, and the management
  menu exposes Gateway overview/status/events alongside WLOC settings,
  devices, logs, health, and component update;
- device profiles own the WLOC node/location mode and no longer expose
  `gateway_default` or “Follow gateway” semantics;
- Component Update is an independent page with firmware, architecture,
  package-format, signature, storage, health, and rollback gates;
- English source strings are used by the LuCI pages; the formal
  `po/zh_Hans` catalogue is present and contract-tested. The lightweight
  front-end compatibility bridge exists only because the AX6S LuCI build
  cannot generate `.lmo` locally and is not a second source of truth;
- Historical AX6S evidence covers migration, provider reuse, RSS/storage,
  reboot, fail-open, and update paths for the former WLOC-only package; a new
  integrated Gateway/WLOC uninstall-first run is still required before release;
- the architecture-correct three-package release build, SHA-256 verification,
  and four-environment Docker install matrix pass;
- real iPhone WLOC traffic, hard power-cut recovery during opkg, flash-full
  fault injection remain explicitly untested. Signed feed publication is
  locally prepared and verified, but gh-pages/tag/release publication and
  external approval remain outside this local worktree until the PR is merged.

The project lead owns architecture, task sequencing, integration, review,
verification, documentation, acceptance, and release. Each implementation task
must be backed by a GitHub Issue, an owned path, an independent `codex/` branch,
focused commits, a handoff capsule, and a review by a different role.

## Ownership boundaries

- `src/`, service state, runtime, proxy, and TLS: `role:engine`.
- `src/exitprobe/`, `src/georesolver/`, OpenWrt network and lifecycle files:
  `role:network`.
- `src/wloc/` and authorized fixtures: `role:protocol`.
- LuCI, rpcd, UCI migration, API docs, packaging and release docs:
  `role:integration`.
- `SECURITY.md`, security ADRs, ACL, and workflow policy: `role:security`.
- `tests/`, `scripts/ci/`, low-resource, OpenWrt, migration, and release tests:
  `role:test`.

## Review and verification gates

Every work package must include tests before implementation where product code
is involved. The project lead will require:

- API contract tests for profile and lifecycle changes;
- failure-path tests for redirect withdrawal and rollback;
- multi-device isolation tests;
- IPv4/IPv6 tests;
- bounded log/cache/temp-file tests;
- low-memory and low-storage measurements;
- OpenWrt Docker verification;
- AX6S upgrade, restart, and real-device checks;
- `./scripts/ci/verify.sh` plus the relevant cross-build and package checks.

No v2 release is accepted while a test only verifies an abstract state machine
but not the corresponding OpenWrt runtime behavior.

## Assistant delegation policy

Code assistants may receive only bounded, disjoint tasks with explicit owned
paths. They must not modify another role's active lease, change credentials,
push releases, or self-approve safety-sensitive work. The project lead reviews
all assistant output, runs the complete verification loop, and owns final
merge, acceptance, and publication.

## Release sequence

1. Freeze v2 API/profile/migration contracts.
2. Complete runtime and per-profile integration.
3. Complete UI, logs, diagnostics, and update center.
4. Run code review and security review.
5. Run unit, integration, OpenWrt, low-resource, migration, and AX6S tests.
6. Build architecture-specific packages and verify checksums.
7. Rehearse upgrade and rollback from v1.2.x.
8. Update README, API, deployment, release, troubleshooting, and security docs.
9. Publish only after the project lead's acceptance checklist is green.
