# WLOC fixture 治理与测试语料契约

- Status: Accepted for offline scaffolding only; no fixture or protocol implementation is authorized.
状态：**已接受为离线治理契约；没有真实 fixture、采集或协议实现授权。** 评审记录见 [Phase 0 review](../../docs/reviews/PHASE0_OFFLINE_SCAFFOLD_REVIEW.md)。

状态：**Phase 0 评审草案；未批准协议实现或真机接入**

本目录只保存可合法用于离线测试、已经审查且可以进入版本控制的
WLOC 测试语料。它不保存抓包工作区，也不构成对 Apple 私有协议字段的推断或
规范。任何字段含义必须来自独立、可审计的证据；未知字段保持未知。

本治理契约已完成离线骨架评审，但这不代表任何 fixture 已获批准。许可证 ADR、
具体 fixture provenance 和后续协议门禁全部通过前，不得基于本目录实现 WLOC
response patch。真实设备 MITM、CA 安装和在线流量采集也不属于 CI 或普通开发流程。

## 1. 允许的语料类别

每个 fixture 必须且只能声明为下列一种类别：

- `synthetic`：由项目自行构造，不包含任何真实抓包字节。它只能验证编码器、
  边界处理和失败路径，不能作为真实 WLOC 兼容性的证据。生成规则及所依据的
  公开规范必须写入 manifest；不得从参考实现源码或未授权样本反推、复制私有
  字段。
- `authorized-sanitized-capture`：源自项目所有者书面批准的隔离实验室采集，并已按本
  文档净化、复核。仓库中只允许出现净化后的最小二进制和非敏感元数据；原始
  流量永远不得进入 Git。

畸形或边界语料仍需声明其来源类别。若由现有 fixture 确定性变异得到，manifest
必须记录父 fixture 的 SHA-256、变异工具版本和精确变异规则。不得把真实抓包
改名为 `synthetic`。

## 2. 采集前授权

任何真实流量采集必须先有可审计的批准记录。批准记录至少包含：

1. 业务目的、负责人、采集人员和安全审查人（仅使用非秘密标识）；
2. 设备所有者的明确同意，以及设备为专用测试设备的确认；
3. 采集开始/结束时间、存放位置、最长保留期和删除责任人；
4. 网络范围：仅批准的测试设备、`gs-loc.apple.com` 或
   `gs-loc-cn.apple.com`、TCP 443；
5. 预期取得的数据、净化方案、许可证/使用权依据和允许的项目用途；
6. 停止条件、事故报告路径和撤销授权后的删除办法。

批准必须由项目负责人和独立安全审查人共同完成。禁止采集普通 HTTPS、其他
LAN 设备、生产用户、UDP 500/4500 或 Wi-Fi Calling 通话流量。不得先采集后
补批，也不得因“仅用于测试”绕过同意或数据最小化要求。

授权记录中只引用仓库外审批系统的非秘密编号；授权书、人员信息或账户信息
本身不得提交到本目录。

## 3. 最小化、去标识与净化

原始数据必须在隔离、加密、访问受控且不被 Git 追踪的临时工作区处理。净化
采取默认拒绝策略：如果无法证明敏感数据已被移除，则不得生成可提交 fixture。

提交前必须移除或不可逆替换：

- API key、token、cookie、Authorization 值、会话材料和所有其他秘密；
- CA 私钥、叶证书私钥、TLS key log、客户端证书及可用于解密或冒充的材料；
- UDID、IMEI、IMSI、ICCID、序列号、电话号码、Apple ID、设备名称以及稳定
  的设备或账户标识；
- MAC/BSSID、SSID、IP 地址、主机本地标识和可关联到个人或设备的日志字段；
- 精确经纬度、海拔、轨迹、时间戳组合和其他可恢复真实位置的信息；
- 与所测协议行为无关的请求、响应、header、证书链、日志和旁路流量。

净化只能修改已经由独立证据确认的字段；不得为了“看起来安全”猜测 Apple
私有字段的含义。若未知字段可能含敏感数据而无法可靠判定，应丢弃整个样本，
而不是删除未知字段后宣称其仍代表真实协议。

用于测试的替换位置必须是明显虚构、项目预先指定且不能映射回真实采集位置的
值。manifest 只能记录验证所需的粗粒度平台/协议信息；不记录真实采集地点、
精确采集时间、人员姓名或设备指纹。

## 4. 二进制真实性与可追溯性

`authorized-sanitized-capture` fixture 必须保持净化后协议载荷的真实字节表示。禁止把
二进制手工改写为“看起来像 protobuf”的样本，或在没有证据时补造字段。允许
的净化应由版本化、可重复的离线工具完成，并产生审计日志；审计日志不得包含
原始正文或敏感值。

每个可提交文件都必须列入同目录的 `manifest.json`。manifest 条目至少包含：

- 稳定的 fixture ID、相对路径和 `synthetic`/`authorized-sanitized-capture` 类别；
- SHA-256、精确字节数、媒体类型及压缩/内容编码；
- 来源说明：合成方法，或仓库外授权记录编号和净化工具版本；
- 许可证/使用权结论及其审批引用；
- 非敏感协议变体信息，例如目标 hostname、ALPN、HTTP 版本、内容编码和粗粒度
  iOS 主版本（确有测试必要时才记录）；
- `redactions[]`：只记录被净化的数据类别、采取的替换/删除动作和仓库外审批
  引用；不得记录原值、可逆映射或 raw-to-sanitized 哈希关联；
- 预期测试结果、必须保留的不变量和允许变化的字段集合；
- 净化复核人、协议复核人、批准日期、复审日期和保留到期日；
- 派生语料的父 SHA-256 与确定性变异规则。

原始文件的哈希和 raw-to-sanitized 映射只能保存在受控的仓库外审计系统中，
不得写进公开或私有 Git 历史。仓库内 SHA-256 仅验证已批准的净化文件。压缩
fixture 的哈希针对提交的压缩字节，同时记录解压后大小上限；禁止嵌套归档。

## 5. 审查、保留与删除

一个 `authorized-sanitized-capture` fixture 至少需要数据负责人、安全审查人和协议审查
人三方批准；采集人不得独自批准自己的样本。`synthetic` fixture 至少需要协议
审查和代码审查。

- raw 数据在净化验证完成后立即安全删除，最迟不得超过采集结束后 7 个自然日。
  法律或事故调查要求延期时，必须在仓库外记录批准人、理由和明确的新到期日；
  延期数据仍不得进入 Git。
- 已提交的授权语料每 180 天、授权条件变化时、或发布前（以最早者为准）复审。
- 授权撤销、保留到期、来源无法证明、净化缺陷或使用权不再成立时，立即停止
  使用并从当前分支删除；同时按安全事件流程评估 Git 历史清理、密钥轮换和已
  发布制品撤回。仅删除工作树文件不代表历史数据已清除。
- 删除和复审结果记录在仓库外审计系统，manifest 更新只保留非敏感状态和引用。

发现秘密、设备标识、精确位置、未授权流量或私钥时应停止评审，不得通过普通
PR 修补后继续；先隔离材料、通知安全负责人，再决定历史清理和凭据轮换。

## 6. 测试语料覆盖契约

语料集应以最少样本覆盖可证明的行为，并清楚区分正向、负向、边界和畸形案例：

- 正向：经批准的合法载荷 round-trip、已证实的协议变体、未知字段保留，以及
  目标字段修改后非目标字段的字节级或语义级不变量；
- 负向：非 WLOC 数据、错误 content type/encoding、缺失必要结构、未知协议版本
  和不允许修改的结构，预期结果必须是拒绝修改或安全透传；
- 边界：经纬度合法边界和正负值、精度范围、空/单/多记录、重复字段、字段顺序
  变化以及恰好位于大小限制的输入；
- 畸形：截断、非法长度、溢出、超大消息、过深嵌套、重复字段滥用、压缩损坏和
  解压倍率炸弹。预期不得 panic、越界、无限分配或产生默认假坐标。

测试名称和预期行为可以描述已观察到的不变量，但不得把未经证实的字段编号、
字段名或语义固化为事实。fuzz seed 必须来自已经批准的 fixture 或纯合成数据，
并继承相同的来源分类和敏感数据限制。

## 7. CI 使用规则

CI 对 fixture 的使用必须完全离线、只读且可重复：

1. 拒绝未列入 manifest、路径越界、符号链接、哈希/大小不符或类别缺失的文件；
2. 拒绝 `.pcap`、`.pcapng`、`.har`、TLS key log、`.pem`、`.key`、`.p12`、
   `.mobileconfig`、raw 请求/响应转储、归档包和未批准日志；
3. 在解析前执行提交大小、解压后大小、嵌套深度、处理时间、内存和并发限制；
4. 运行秘密/高风险标识扫描，并对 manifest 结构、SHA-256、许可证状态、审批状态
   和保留期限执行硬失败校验；
5. 不联网获取 fixture，不访问真实 Apple endpoint，不安装或生成受信 CA，不读取
   Agent 凭据，也不把 fixture 正文写入日志或测试制品；
6. `synthetic` 测试通过不得解除真实兼容性门禁；只有审查通过且未过期的
   `authorized-sanitized-capture` 样本可以作为 Phase 0 协议证据；
7. parser、patcher、fuzz 和回归测试只能消费 manifest 允许的相对路径。失败时
   输出 fixture ID、规则和摘要，不输出正文。

PR 必须说明新增/变更语料的类别、授权或生成依据、净化与审查证据、覆盖的测试
案例、风险以及删除/回滚办法。任何门禁失败都阻止 fixture 合入，不能通过更新
golden 输出掩盖解析或净化错误。

## 8. 明确禁止

本目录及整个仓库禁止提交：原始抓包、生产流量、真实设备标识、精确用户位置、
CA/叶证书私钥、TLS 会话秘密、凭据、未授权样本，以及从 AGPL 参考实现复制或
派生而许可路线尚未批准的语料/字段知识。不得以 Base64、压缩、加密文件或 Git
LFS 规避这些限制。

当样本真实性、授权、净化或许可证任一项无法证明时，结论是“不纳入语料库”，
而不是降低门禁。

本治理文档与许可证 ADR、威胁模型全部被接受后，下一步仍只允许建立 Go module、
离线 manifest validator、CI 骨架和通用协议安全契约测试。不得加入 Apple 私有字段
编号或语义、真实抓包字节、response patch、CA、MITM 或 live traffic。
